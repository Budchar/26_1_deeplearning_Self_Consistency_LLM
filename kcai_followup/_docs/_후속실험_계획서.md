## 3. 본인 4개 실험 — 상세 계획

### 실험 1 (본인 우선순위 1): Activation patching

**목적**: "L2-L4 MLP가 hallucination 결정"의 인과 증거 (Meng et al. ROME 방식)

**대상 모델**:
- Phase 1 단계: Qwen2.5-1.5B-Instruct (DPO 변형 자체학습 어려우면 Qwen2.5-1.5B vs Qwen2.5-1.5B-DPO 검증용)
- Phase 2 단계 (5070 inference로 가능 시): Mistral-7B NousHermes ↔ OpenHermes

**방법**:
1. 두 모델 동일 prompt에 대해 모든 layer hidden state 추출
2. NousHermes의 L2, L3, L4 MLP output을 OpenHermes 같은 layer에 주입 (replace)
3. OpenHermes의 최종 출력 변화 측정 (정답률, hallucination score)
4. 역방향도 동일하게 (OpenHermes MLP → NousHermes 주입)
5. control: 다른 layer (L20 등) patching했을 때 효과 없음을 확인

**평가**:
- 정답률 변화 (TriviaQA, NQ-Open, SQuAD 각 200 문항)
- SEPs score 변화
- statistical significance: paired t-test, n=200

**코드 구조**:
```
experiments/dl_team_followup/01_activation_patching/
├── extract_hidden.py        # 모든 layer hidden state 저장
├── patch_run.py             # patching + 출력 측정
├── analyze.py               # 통계 검정
├── results/
└── plots/
```

**성공 기준**: patching 시 정답률 변화 |Δ| > 5pp, p < 0.05

**위험·완화**:
- 두 모델 dim mismatch 가능 → 같은 base (Mistral-7B-v0.1) 모델만 사용
- 5070 12GB로 7B 두 개 동시 로딩 불가 → sequential 처리 (hidden state 저장 후 로딩)

### 실험 2 (본인 우선순위 2): Steering vector

**목적**: hallucination의 linear representation 검증 + inference-time 조작 가능성

**대상 모델**: Qwen2.5-7B-Instruct, Mistral-7B-Instruct-v0.3, Llama-3.2-3B-Instruct

**방법**:
1. 정답 케이스 N개 hidden state 평균 → h_correct
2. 오답 케이스 N개 hidden state 평균 → h_wrong
3. 방향 벡터 d = h_wrong - h_correct (각 layer별)
4. 생성 중 hidden state에서 α·d 빼기 (또는 더하기)
5. α 스윕 (α ∈ [-2, -1, -0.5, 0, 0.5, 1, 2])
6. 정답률 변화 plot

**평가**:
- α vs 정답률 곡선 (모델·데이터셋별)
- 최적 α (정답률 최대인 지점)
- 과도 steering 시 perplexity 폭주 여부 (generation quality)

**코드 구조**:
```
experiments/dl_team_followup/02_steering_vector/
├── compute_direction.py     # d = mean(wrong) - mean(correct)
├── steer_generate.py        # generation with hook
├── alpha_sweep.py
├── results/
└── plots/
```

**성공 기준**: α < 0에서 정답률 > baseline +3pp (linear representation 가설 지지)

**위험·완화**:
- linear hypothesis 안 맞을 수 있음 → 결과 negative여도 결과 자체가 paper 가치
- generation collapse 위험 → α 작게 시작, perplexity 모니터링

### 실험 3 (본인 우선순위 3): Multi-metric trajectory

**목적**: 0.682 ± 0.131 peak depth가 진짜 의미 결정 경계인지 multi-modal 입증

**대상**: Phase 1 5 모델 × 3 데이터셋 = 15 cell (기존 hidden state cache 재사용)

**방법**:
각 (모델, 데이터셋, layer) tuple마다 6개 지표 계산:
1. **Mutual Information** (hidden state ↔ correct label) — sklearn.feature_selection.mutual_info_classif
2. **Representation separability** — Fisher discriminant ratio 또는 silhouette score
3. **Logit entropy** (Logit Lens 적용)
4. **Answer-token probability** — 정답 토큰 logit 확률
5. **Attention entropy** — 모든 head 평균
6. **Residual norm** — ||h_ℓ - h_{ℓ-1}||

→ 정답·오답 그룹별로 6개 지표 trajectory plot. 어느 layer에서 분기하는지 확인.

**평가**:
- 6 지표 모두 동일 layer 근처(예: 0.55-0.85 depth)에서 정답·오답 분기 확인 시 → 0.68 robust
- 일부만 분기 → probe artifact 가능성

**코드 구조**:
```
experiments/dl_team_followup/03_multi_metric_trajectory/
├── compute_metrics.py       # 6 지표 계산 함수
├── trajectory_analysis.py   # layer별 정답·오답 분기 찾기
├── plot_trajectories.py     # 6 panel grid
├── results/
└── plots/
```

**성공 기준**: 최소 4/6 지표가 같은 depth 구간(0.55-0.85)에서 분기

**위험·완화**:
- Mutual Information 계산 비용 크면 sampling 사용
- Attention entropy는 layer마다 head 수 다를 수 있음 → 평균 처리

### 실험 4 (본인 우선순위 4): Layer/Sublayer probe 재현

**목적**: wclee 결과 재현성 확보 (paper review reproducibility)

**대상**: 종합보고서 §5-7에 나온 11 모델 (Mistral 8변형 + EXAONE + Qwen + 기타)

**방법**:
1. wclee 코드 (만약 있으면 받고, 없으면 본인 재구현)
2. 동일 데이터셋·동일 probe 알고리즘으로 각 모델 layer probe 재학습
3. peak layer 추출
4. wclee 보고 결과와 |Δ| < 2 layer 이내 일치 확인

**대안 (wclee 코드 없을 때)**: 본인 자체 구현
- Logistic regression on hidden states (sklearn)
- Train/test 5-fold cross-validation
- AUROC per layer

**코드 구조**:
```
experiments/dl_team_followup/04_layer_probe_replication/
├── replicate_probe.py       # 11 모델 × layer probe
├── compare_with_wclee.py    # |Δ| 분석
├── results/
└── plots/
```

**성공 기준**: 11 모델 중 9 이상에서 peak layer가 wclee 결과와 |Δ| < 2

**위험·완화**:
- 7B 모델 11개 inference 시간 큼 → 우선순위 5개부터 (Mistral 8변형 핵심)
- wclee와 다른 결과 나오면 그 자체가 paper에 별도 섹션 (negative finding)

## 6. 우창님 5-6번 가정 메모

### 5번: 동일 base SFT vs SFT+DPO 통제 학습
- **A100 가정 사양**: 80GB
- **모델**: Mistral-7B-v0.1 (base, OpenHermes·NousHermes의 공통 base)
- **데이터**: OpenHermes-2.5 (SFT), Argilla-DPO-mix-7k (DPO preference) — 둘 다 공개
- **변형 3종**:
  - A. Base (학습 X, control)
  - B. SFT only (OpenHermes-2.5 1 epoch)
  - C. SFT + DPO (B 모델 위에 Argilla DPO 1 epoch)
- **예상 시간**: A100 80GB FP16 full fine-tune 20-40h per 모델, 총 60-120h
- **본인 역할**: 평가 코드 (Layer probe + SEPs) 제공, 결과 분석
- **paper 통합**: §Causal Claim (5번 결과가 가장 강한 reviewer 반박 방어)

### 6번: factual vs style/random DPO 4종 (자원 여유 시)
- **모델**: 5번과 동일 base (Mistral-7B-v0.1 SFT만 적용한 B 모델)
- **DPO 데이터 4종**:
  - factual: TruthfulQA preference (또는 자체 큐레이션)
  - helpful/harmless: Anthropic HH-RLHF
  - style: style-controlled preference (구하기 어려움)
  - random: chosen/rejected swap (즉시 생성 가능)
- **예상 시간**: A100 100-200h
- **본인 역할**: 데이터셋 큐레이션 + 평가
- **paper 통합**: §Mechanism Precision (DPO 자체가 아니라 factual preference가 핵심)

### 우창님 부탁 안 됐을 때 대안
- 5번 다운스케일: Qwen2.5-1.5B base에서 같은 통제. 5070 LoRA 50-100h
